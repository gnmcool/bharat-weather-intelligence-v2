# D2 data-access decision note — Open-Meteo free, Open-Meteo paid, or direct ERA5

**Status (30 Sep 2026):** documentation only. **The decision is OPEN.**
- The D2 plan stays frozen at `f4d98b1` (`docs/M4.4-D2_PLAN.md`) and is not modified by this note.
- No ERA5 has been retrieved, no D2 code exists, no release has been created, and `main` is unchanged.
- The M4.4 methodology (VM-1.1, M4.4-D-SPEC-1.0) is unchanged by every option. Only the **data-access
  mechanism** differs.
- This note documents trade-offs; it does not rank the options.

Facts were checked on 30 Sep 2026 against:
- Open-Meteo terms and pricing pages;
- the Copernicus Climate Data Store (CDS) ERA5 dataset page and its API guide;
- ECMWF's ERA5 documentation;
- the BWI code (CORE `2840f8d`, V2 `main` `dcecb8f`).

Items marked "unverified" could not be confirmed from public pages.

---

## 1. Four things that must not be conflated

| Subject | Current status | Governed by |
| --- | --- | --- |
| **BWI's current development status** | Free for farmers, citizens and public-interest users: no payments, subscriptions or advertising (owner statement, 30 Sep 2026). **Whether this qualifies as "non-commercial" under each provider's terms is not assumed.** It is part of the open decision | the owner, and each provider's own definition |
| **Eventual commercialisation** | Possible later; not planned or implemented. The dependencies are listed in the commercialisation audit (Open-Meteo, Vercel Hobby, GitHub Pages, EUMETSAT live imagery, IMD, SACHET, boundaries) | the owner, at the time |
| **Licensing of newly retrieved D2 ERA5 data** | **Nothing retrieved.** Its status will be set by the access route chosen here and recorded in every D2 manifest | this decision |
| **Status of the existing M4.2 historical archive** | Retrieved through the **free, non-commercial** Open-Meteo previous-runs and historical services (31 monthly releases `history-2024-02` … `history-2026-08`; basis of the M4.4-A/B/C results). **Its future commercial-use status is explicitly unresolved.** It is **not** relabelled, re-retrieved or altered by this note or by any option below | unchanged; to be settled separately |

Background on the M4.2 archive:
- The Open-Meteo **data** are licensed CC-BY 4.0.
- The free **service** is restricted to non-commercial use.
- Whether data obtained through the free service may later be used commercially is a legal question that this note
  does not answer.

## 2. The options

- **A.** Open-Meteo **free / non-commercial** historical API for the current BWI phase, as D2 is written.
- **B.** Open-Meteo **paid / commercial** from the start, via the customer endpoint with an API key.
- **C.** **Direct ERA5 access** from the producer's distribution: the Copernicus Climate Data Store,
  `reanalysis-era5-single-levels`, total precipitation.

### 2.1 Licensing and use rights

| | A | B | C |
| --- | --- | --- | --- |
| Service terms | free API **for non-commercial use only**; commercial use requires a paid plan | a paid plan includes "a commercial use licence and an API key for the dedicated customer endpoint `customer-api.open-meteo.com`" | free CDS account; each dataset's terms must be accepted **manually on the dataset page** before any download |
| Data licence | CC-BY 4.0 (attribution required) | CC-BY 4.0 (attribution required, including for commercial use) | the ERA5 page states a CC-BY licence, which allows commercial use with attribution |
| Depends on BWI's commercial status | **yes**: valid only while BWI's use qualifies as non-commercial under Open-Meteo's terms (not assumed) | no | no |

### 2.2 Effect on D2

| | A | B | C |
| --- | --- | --- | --- |
| D2 plan (`f4d98b1`) | usable **as written** (§3–§4 name exactly this service) | usable with **two changes**: the host becomes `customer-api.open-meteo.com` and an `apikey` parameter is added (a secret) | **§3 source, §4 request and §7 call accounting must be rewritten** for the CDS. §5 (points, 30 km rule, IST day, E/G), §6 (70-day wait), §8–§13 and the methodology are unchanged |
| Plan tier needed | none | **Professional plan or higher**: the historical (ERA5) API is not included in the Standard plan (pricing page). The price is not shown on the static page; confirm at subscription | none |
| Grid cell | Open-Meteo's land-cell selection (90 m DEM), as used for the M4.4-B ERA5 values | same as A | BWI's own explicit nearest-cell rule on the 0.25° grid. **Cells may differ from those used for the M4.4-B ERA5 values**, so the difference must be documented |
| Version marker | ERA5T and final cannot be told apart; R1 (70-day wait) mitigates this | same as A | the CDS documents ERA5T versus final (`expver`). **R1 can be verified, not only assumed** |
| Secrets in the D2 workflow | none | an Open-Meteo API key (GitHub secret) | a CDS API key (GitHub secret) |

### 2.3 Effect on future commercialisation

| | A | B | C |
| --- | --- | --- | --- |
| D2 data retrieved now | same unresolved status as the M4.2 archive; may need re-retrieval under B or C if BWI becomes commercial | retrieved under a commercial licence from the first month | retrieved under a licence that allows commercial use from the first month |
| Other Open-Meteo dependencies (CORE live forecasts, V2 daily archive) | unaffected; they remain an open item of the audit | the same paid key could later cover CORE (`BWI_OPENMETEO_API_KEY`) and the daily archive, a separate decision; the plan tier must include forecast APIs | unaffected; CORE's and the archive's Open-Meteo use stays a separate open item |
| Ongoing cost | none | a recurring subscription (Professional or higher) | none (free account) |

### 2.4 API / request limits

| | A | B | C |
| --- | --- | --- | --- |
| Documented limits | < 10,000 calls/day, 5,000/hour, 600/minute, applied per IP; GitHub runners share IPs | Standard 1M calls/month; **Professional 5M/month** (required for historical); Enterprise 50M+; tied to the key | not specified on the CDS API page; requests are queued (unverified: size limits and queue times) |
| D2 need | ≈ 80–83 counted calls per month (≤ 200 budget) | same counting (> 10 variables or > 14 days count as more) | a small number of requests per month; accounting by requests and download size instead of Open-Meteo calls |
| Latency | ERA5 5 days behind; D2 waits 70 days anyway | same | ERA5 about 5 days behind; queue time adds minutes to hours (unverified). D2 waits 70 days anyway |

### 2.5 Provenance implications

| | A | B | C |
| --- | --- | --- | --- |
| Source recorded | Open-Meteo historical API, `models=era5`, free tier | Open-Meteo customer API, `models=era5`, the plan name (the key never recorded) | CDS dataset id, request parameters, `expver` per timestep, CDS request id, file checksum |
| Intermediary processing | Open-Meteo's storage and land-cell selection (undocumented details) | same as A | none beyond BWI's documented extraction |
| Licence field in the manifest | "CC-BY 4.0; retrieved under the non-commercial free service" | "CC-BY 4.0; retrieved under a commercial Open-Meteo licence (plan)" | "ERA5 licence as stated on the CDS dataset page, accepted for account X on date Y" |

### 2.6 Can the existing M4.2 historical data be treated the same way?

| | A | B | C |
| --- | --- | --- | --- |
| M4.2 forecast history (Open-Meteo previous-runs API: ECMWF/GFS/ICON at nominal leads) | yes: same route and terms as A | **no**: M4.2 was retrieved under the free tier. A paid plan does not change how existing data was obtained. Whether previous-runs is included in a paid plan, and whether past retrievals are covered, is unverified | **not applicable**: the CDS has no equivalent of Open-Meteo's previous-runs forecast archive, so there is no direct-ERA5 substitute for the forecast part |
| M4.2 ERA5 reference part | same route as A | same as the row above | could be re-derived from the CDS as a **new, separately versioned** supplement; cell-selection differences from the Open-Meteo ERA5 values must be documented |
| M4.2 IMD and METAR parts | not Open-Meteo; separate terms (IMD gridded-data terms unconfirmed; IEM METAR) | same | same |

In **all** options the existing M4.2 releases stay immutable and unchanged, and their status stays unresolved until
decided separately.

### 2.7 Migration and reproducibility

| | A | B | C |
| --- | --- | --- | --- |
| If BWI later needs commercial-status reference data | re-retrieve affected months under B or C as **new versioned releases** (`ref-era5-YYYY-MM-v2`, reason "access-route change"). Every result names the version it used; old releases stay | nothing to migrate for D2 | nothing to migrate for D2 |
| Reproducibility of a month | re-request through the same service. Values are expected to be identical for final ERA5, but this is not guaranteed (Open-Meteo processing) | same as A, with the key | re-request the same dataset; the `expver` check detects version changes |
| Consistency with the M4.4-B ERA5 values (historical, via Open-Meteo) | same route | same route | different route; values may differ slightly by cell and processing. D2 is prospective-only, and IMD/ERA5 or historical/prospective results are never combined, so this is a documentation matter, not a methodology change |

### 2.8 Expected engineering effort (estimates for D2 only)

| | A | B | C |
| --- | --- | --- | --- |
| Implementation | as planned: request-file workflow, bounded client, extraction, manifest, tests (≈ 1.5–2 days) | A plus key/host configuration and a GitHub secret (≈ + 0.5 day), plus subscription administration | a CDS client (a new dependency), account and licence acceptance, gridded-file handling, nearest-cell extraction, `expver` checks, queue-aware job timeouts, revised accounting (≈ 3–5 days), **plus a D2 plan revision** of §3, §4 and §7 before implementation |
| Ongoing | monitor free-tier compliance | subscription renewal | CDS account and licence maintenance |

## 3. What stays the same under every option

- The ERA5 role (secondary / interim rain reference; IMD primary once 2026 exists; never combined).
- The IST calendar-day definition with the stated 30-minute offset, the 30 km rule, E/G missing data, the 70-day
  final-data wait (R1), the one controlled repeat (R2), no partial publication, immutable releases, manifests,
  archive-index records and the correction procedure.
- The M4.4 methodology, CORE and V2.
