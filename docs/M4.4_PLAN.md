# M4.4 implementation plan

**Status (30 Sep 2026):**
- **M4.4-A: COMPLETE** (owner acceptance, 30 Sep 2026). The published Gate 2 record is the single authoritative
  result set: archive-index `history/verification/m4.4-a-gate2-9d9e204/`, census `m4.4-a-census-2@55030a4`, VM-1.1.
  The 30 held primary cells stay held. The source-resolution limitation is recorded in VM-1.1 §21 and in
  `history/verification/annotations/`.
- **M4.4-B: computed, awaiting owner review** (rain event verification, weather-model event detection only;
  archive-index `history/verification/m4.4-b-8f86280/`).
- **M4.4-C and M4.4-D:** not started.

Implements **VM-1.0** as amended by VM-1.1 (`docs/VERIFICATION_METHODOLOGY.md`). Each sub-phase starts only on the
owner's approval.

## 0. Constraints (apply to every sub-phase)

- Inputs are the immutable releases only (`history-2024-02` … `history-2026-08`, `history-imd-raw-2024/2025`, later the
  prospective `archive-daily-*`). Every input file is checked against its manifest SHA-256 **and** the archive-index
  record before use; a mismatch stops the run.
- No modification of the historical archive, the prospective archive, CORE or V2. No Open-Meteo, IMD or IEM calls
  (all data is already archived; no quota use).
- Methodology version `VM-1.0` is recorded in every result; a changed rule means a new version.
- Explicit eligibility (VM-1.0 §6) and missing-data handling (A–G excluded, never zero, never counted as error).
- No global model ranking, no overall BWI score, no probability/confidence language, Earth2Studio GFS never an
  independent model, ERA5 never presented as a neutral observation, no fabricated observations, no new thresholds.
- Offline synthetic-data tests with known answers **before** any run on the archive (§6).

## 1. Architecture

A new, separate package `verification/` (reads `history/` and `archive/` outputs, imports nothing that writes to them).

| Module | Responsibility |
| --- | --- |
| `inputs.py` | download releases by tag; verify SHA-256 against manifest and archive-index; apply recorded annotations (e.g. `2024-02-ecmwf-archive-start`); refuse mixed `historical_nominal` / `prospective_exact` inputs in one experiment |
| `eligibility.py` | build forecast/reference pairs from the matched tables; exclude A–G; window and lead checks; spatial rules; intersection samples for comparisons; region / season / high-altitude labels |
| `metrics.py` | pure functions: bias, MAE, RMSE; contingency table, POD, FAR, CSI, frequency bias, base rate (undefined → null, never 0) |
| `bootstrap.py` | 95% block bootstrap on whole valid dates, 7-day blocks, 1,000 iterations, fixed seed; paired version for differences |
| `floors.py` | VM-1.0 §11 publication floors → `status = ok \| insufficient sample \| not verifiable` |
| `agreement.py` | k-of-3 counts over ECMWF/GFS/ICON only (rejects any other model name) |
| `results.py` | VM-1.0 §16 schema; wording templates; limitation codes |
| `run.py` | runs one experiment config; writes results + run record (§17 provenance) |

Output per run: a results table (Parquet + CSV) and a run record (inputs with SHA-256, annotations, code commit,
methodology version, config and its SHA-256, seed, result SHA-256). Storage location: **question Q1** (§7).

## 2. Sub-phases

Each sub-phase has two gates: (1) an **eligibility census** — sample counts per result cell and whether each meets
its floor, no metric values — reviewed by the owner; (2) the metric run, reported for review. Nothing is published
to the V2 site.

### M4.4-A — continuous forecast verification

| Experiment | Forecast | Reference | Window | Scope |
| --- | --- | --- | --- | --- |
| A1 | tmax, tmin | ERA5 reanalysis | IST day | 36 points, 31 months; labelled "agreement with ERA5 reanalysis" |
| A2 | tmax, tmin | METAR | IST day | matched stations meeting the per-station floor (≥ 90 eligible days); per station only |
| A3 | rain | IMD | 08:30 day | 34 points, 1 Feb 2024 – 30 Dec 2025; all days, and the 2.5 mm rainy-day split (analytical only) |
| A4 | rain | ERA5 reanalysis | IST day (0830 as cross-check) | 36 points, 31 months; secondary |

Metrics: bias, MAE, RMSE with 95% intervals; per model (ECMWF, GFS, ICON) × variable × Day 1–7 (ICON 1–6; lead 7
comparisons ECMWF vs GFS only), then by season, region (islands separate), high-altitude flag where floors are met.
Model differences: paired intersection sample, paired bootstrap interval of the MAE/bias difference; stated per
variable, lead, window, reference and period only. ERA5-based differences never support a ranking. Gust: **not in
M4.4** (no observational reference; VM-1.0 §3).

### M4.4-B — rain event verification

Thresholds: CORE M-RAIN only — 35.6 / 64.5 / 115.6 mm per 24 h. Primary reference IMD (08:30 day, 2024–2025),
secondary ERA5 (labelled). Per model × lead × threshold: hits, misses, false alarms, correct negatives, base rate,
POD, FAR, CSI, frequency bias with intervals; floors ≥ 20 reference events (POD) / ≥ 20 forecast events (FAR). By
season where floors allow (expected: mostly monsoon; winter mostly "insufficient sample").

### M4.4-C — model-agreement analysis

ECMWF, GFS, ICON only; cells where all three are eligible (leads 1–6; no gust; B/C cells excluded). For each
threshold: k = 0/1/2/3 models ≥ τ; per k: n, reference events, observed relative frequency with interval; secondary
breakdown by model combination. Floors: n ≥ 100 and ≥ 10 events per k. Fixed wording: "In the archived sample … when
k of 3 models forecast ≥ τ, the reference reached ≥ τ on x of n days." No probability, chance or confidence.

### M4.4-D — prospective CORE risk verification (documented, **not implemented**)

- Data: `core_risks_<D>.parquet` in the prospective daily releases, from 28 Sep 2026; CORE's earlier outputs do not
  exist.
- Start condition: **≥ 90 days** of prospective archive (earliest ≈ 27 Dec 2026) **and** the event-count floors per
  risk type and level (VM-1.0 §11) — whichever is later.
- Scope when started: rain (M-RAIN) only as a system risk (heat/cold are a future extension; wind has no observed
  reference; others not verifiable). Hit / miss / false alarm / correct negative per VM-1.0 §10.
- **Known blocker:** IMD 2026 rain is not published, so prospective rain verification against IMD cannot start until
  IMD publishes (see Q4). ERA5 would be secondary only.
- C2 "historical rule replay" (approved in VM-1.0) and METAR occurrence (thunderstorm, fog; station-level) are not
  in A–D; proposed as optional later items (Q2).

## 3. Sequence

1. Build `verification/` with offline tests only (§6). Review.
2. Eligibility census for A and B (counts only). Review.
3. A1–A4 metric run and report. Review.
4. B metric run and report. Review.
5. C census, run and report. Review.
6. D stays documented; re-assessed when the prospective archive reaches 90 days.

## 4. Deliverables per sub-phase

Results table and run record (committed append-only), a short report (measured result · limitation · interpretation
per VM-1.0 §14), and the list of cells reported as "insufficient sample".

## 5. Effort and risk

- No external API use; inputs ≈ 15 MB of Parquet plus two 25 MB IMD files already verified.
- Main risks: silent mis-joins (mitigated by eligibility tests and censuses), correlated samples (block bootstrap),
  multiple comparisons across many cells (Q3), and reading ERA5 results as skill (labels and wording tests).

## 6. Test plan (all offline, before any archive run)

**Known-answer metric tests**
- bias, MAE, RMSE on small hand-computed vectors (including negative errors and a single outlier for RMSE vs MAE).
- Contingency: a hand-built set with known a, b, c, d → POD, FAR, CSI, frequency bias, base rate; zero-denominator
  cases return null, not 0.
- Agreement: synthetic days with known k per model combination → known counts and frequencies.
- Bootstrap: fixed seed gives identical output; blocks are whole dates in 7-day blocks; on synthetic data with a known
  mean error the interval contains it; the paired interval of two identical models is centred on 0.

**Eligibility and missing-data tests**
- Rows with A, B, C, D reasons are excluded; a missing value is never scored as 0; a C outage never appears as an
  error.
- Intersection sample: a comparison drops (point, date, lead) cells where any compared model or the reference is
  missing; ECMWF gust and ICON lead 7 never enter a comparison.
- Windows never mixed (IST day vs 08:30); nominal and exact leads never pooled (loader refuses).
- METAR only for matched stations; IMD only ≤ 30 km; islands never merged into a mainland region; high-altitude points
  flagged.
- Agreement rejects any model other than ECMWF/GFS/ICON (e.g. `e2s_gfs025`).
- Floors: a cell below its floor returns `insufficient sample` with n and no value.

**End-to-end synthetic archive**
- Fake monthly releases (reusing the history test fakes) with planted truths — e.g. model = reference + 1.0 °C
  (bias 1, MAE 1, RMSE 1), a planted set of rain events with a known contingency table, planted A/B/C gaps — run
  through the whole pipeline; outputs match the planted answers and the VM-1.0 §16 schema.

**Integrity and reproducibility**
- A tampered input (checksum ≠ manifest or index) stops the run.
- Same inputs + config + seed → byte-identical result table (same SHA-256).
- Every result row carries `methodology_version = VM-1.0`, code commit, input releases and SHA-256.

**Wording**
- Output labels contain no "probability", "chance", "confidence", "best model" or "overall score"; ERA5 rows are
  labelled "ERA5 reanalysis".

**Regression**
- history, archive, api-v2, CORE contract, M1, M2, M3 suites unchanged and passing.

## 7. Open scientific questions for approval

- **Q1 — where results live.** Proposal: small results tables and run records committed append-only to
  `archive-index` under `history/verification/<run>/` (not releases, not the V2 site). Alternative: immutable
  `verification-<run>` releases.
- **Q2 — optional items.** Include C2 "historical rule replay" (rain) and METAR station-level occurrence
  (thunderstorm, fog) as M4.4-E after A–C, or defer?
- **Q3 — multiple comparisons.** Many cells (model × variable × lead × season × region). Proposal: publish all
  intervals unadjusted but label cell-level model differences "exploratory"; only pre-declared primary comparisons
  (per variable, all seasons pooled, IMD for rain) may be stated as findings. Alternative: Holm correction.
- **Q4 — IMD 2026 and M4.4-D.** Prospective CORE rain verification cannot use IMD until IMD publishes 2026. Wait for
  IMD (or IMERG, B6), or allow an ERA5-only interim result clearly labelled secondary?
- **Q5 — gust.** Confirm gust is excluded from M4.4 entirely (no ERA5-only exploratory table).
- **Q6 — temperature and elevation.** Forecast and ERA5 point values may use different terrain handling. Proposal:
  record grid and point elevations and report bias by elevation band as a diagnostic; never adjust values.
